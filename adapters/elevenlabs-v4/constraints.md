# ElevenLabs Eleven v4 adapter

- Single-speaker voice, explicit eleven_v4 or eleven_v4_turbo, up to 2,000 characters, params.voice_id, MP3 narration. No automatic model fallback.
- Discover all tools/list pages and require an explicit model enum/const. Support legacy text speech tools and creative_generate_speech only with a compatible creative_get_flow_run_status schema. Creative calls always request one generation with estimate_only false.
- Generate once, poll only the returned flow/session, bind the completed model/prompt/voice, and pin MP3 inside the run. Reject failure, changed identity, unexpected outputs, redirects, and oversized audio. Trust ElevenLabs URLs and only the observed xi-backend content-generation MP3 path on Google Storage.
- Keep a run-owned exclusive submission journal before a paid call. Unknown/pending/failed outcomes never trigger another generation, including on later invocation. Journals contain no tokens or signed URLs. Recovery uses status lookup and explicit completed-result import, never journal deletion to resubmit.
- probe.mjs is read-only discovery; models is local contract validation. Neither confirms voice entitlement, credits, pricing, or successful generation.
- Gate 1 approved Coordinator execution remains required. The standalone HTTP client uses an existing MCP bearer or the explicit @tsugite-elevenlabs-v4-keychain selector. Dedicated OAuth requires an explicitly selected, maintainer-approved dedicated HTTPS client metadata document, explicit authorization/storage approval, pinned discovery, S256/state/issuer/resource checks, and a dedicated macOS Keychain item. It never extracts other clients' credentials, requests all advertised scopes, registers clients dynamically, or starts interactive login during generation. Approved real OAuth, Keychain save/readback, authenticated tools/list, and one separately approved paid narration through the dedicated grant succeeded. Live refresh remains unverified; mocked transport and actual two-process rotation/uncertain-save fixtures are verified. The paid verification used an isolated orchestrator Gate fixture and the production child CLI with live transport, not the full public CLI Gate flow.
- import-result.mjs explicitly imports a completed request-bound result without MCP calls or generation. It is not an automatic fallback and does not prove authenticated CLI E2E. Report source as imported and retain original measured credits separately from any claim of new charges.
- Creative measured billing is preserved. Legacy credits zero/unmeasured never means free.
- Current authenticated connector schema offers v4 but not v4 Turbo. Turbo v2.5 is a different model. Native connector generation, real-result import, offline orchestrator integration, and authenticated CLI E2E must be reported separately.

- New paid submissions additionally require an explicit schema-verified estimate-only quote, a current price/limit, a Gate 1 billing digest, matching profile/grant epoch/schema, and a Gate-bound canonical project context. Plain project YAML cannot supply runtime billing evidence. Credits with unknown fiat amount are labeled separately; no currency conversion or provider billing cap is inferred.
- Versioned adapter-owned receipts retain the permanent journal, accepted IDs, budgets and asset proof. Public resume preview is local-only; apply never submits. Unknown/old/partial records remain blocked. Project-local unresolved request digests block a new run ID. Polling wait/count and download budgets survive restart.
- Public auth login preserves both approval guards. Status does not refresh/save; connection lists use non-secret cache only. Refresh intents and locks contain no token bytes. Token/binding snapshots and a profile lock guard grant replacement through paid acceptance.
- The shared 2D card shows request/cost/next action. Unknown offers inspection only. Normal recovery requires the original approval; explicit audit-original writes only to its original receipt and cannot adopt into the current manifest/QC/Gates. Content changes fail closed.
