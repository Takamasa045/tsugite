# v1からv2への移行判断（推奨案）

この文書は、継手の所有者が「次に何をするか」を決めるための材料です。**決まった方針ではありません。** 作業者がリポジトリと公開リリースから確認できた事実と、所有者が別途渡した手元の案件数をもとに、推奨案を書いています。採用・変更・見送りは所有者が決めます。

いまの位置：

- いまの制作の正本は **v1 0.18.0**（`project.yaml` の案件）。
- 試用用の独立配布は **v2 2.0.0-alpha.5**（`tsugite.yaml`）。実課金の受け入れ確認と、第三者3人の初回試用はまだ完了していません。
- この文書は判断用です。プログラムの動き、版番号、公開タグは変えていません。

案件名は書いていません。件数は所有者提供の集計です。

## 5つの段階

下の順で進めます。前の段階が終わる前に、次の段階の「公開」や「課金」を始めません。

| 段階 | やること | 完了とみなす条件 | 所有者の承認 |
| --- | --- | --- | --- |
| 1. コードだけで埋められる差 | 下の表で「v2 で対応」と選んだ機能のうち、課金や外部アカウントが不要な差を埋める。確認ページ・予算・秘密情報の扱いを緩くしない | 対象の差がテストで確認できる。文書が実装と一致する。有料API・`run` / `render` を使っていない | どの差をこの段階の対象にするかの確認。課金は不要 |
| 2. 有料サービスの受け入れ | 要件 **P08**（PixVerse / Kling）、**P10**（ElevenLabs）、**B04**（失敗・再実行時のクレジット整合）を、実際の課金単位で確かめる | 所有者が選んだ1件ずつの実リクエストで、見積もり・実行・確定（または失敗の保留）が確認ページ経由で記録される。合成テストだけを「受け入れ完了」としない | **必須。** 使うアカウント、上限、対象サービスを所有者が指定するまで始めない |
| 3. 人による試用とissue公開 | 要件 **U07** / **S01**（作者以外3人、3つのOS、10分以内の初回結果）と、**D06**（良い最初のissueを少なくとも5件公開）。要件 **M06**（4フェーズ・14週間・各フェーズの独立ユーザーゲート）のうち、**いまのalphaに対するゲート**はこの3人試用で見る。M06全体はここでは完了にしない | 3人の試用記録（所要時間、最初に詰まった点、個人情報なし）。GitHubに少なくとも5件の公開issue。M06の残りフェーズは未完了のまま | **必須。** 誰に頼むか、どのissueを出すかを所有者が選ぶ |
| 4. 既定をv2へ切り替える | 要件 **M07**（新しい制作をv2から始める）、**M02**（v1保守の置き場所）、**S05**（fork利用者への案内）、**D08**（メンテナの実名）と、版 **2.0.0**。段階3のalphaゲートだけでは M06 全体を満たさないため、残りのフェーズゲートを進めるか見送るかを所有者が決める | 新しい案件の案内がv2を既定にする。v1の残し方が文書化される。2.0.0の公開範囲が所有者の指定どおり。M06の残りの扱いが文書化される | **必須。** 既定の切り替えと 2.0.0 は所有者の明示承認があるまで行わない |
| 5. v1を畳む | 要件 **P15**（実験部品の置き場所）、**S02**〜**S04**（公開後の本数・外部プラグイン・月次更新） | 実験部品の行き先が決まる。v1停止の時期と、残すもの（既存案件の完走など）が文書化される。公開後の目標は「公開してから測る」ものであり、この段階の開始条件ではない | **必須。** v1の停止・移動・外部通知は所有者の明示承認があるまで行わない |

いまのalphaを「正式なv2」や「制作の既定」にはしません。段階4の承認があるまで、既存の `project.yaml` 案件はv1で続けます。

段階3の3人試用は、M06が求める「各フェーズの独立ユーザーゲート」の**いまのalpha分**です。4フェーズ・14週間の全体を段階3で完了扱いしません。段階4へ進む前に、所有者が残りのフェーズゲートをどう扱うかを決めます。

## 推奨案の読み方

3つの選択肢の意味は次のとおりです。

- **v2 で対応**：v2の本番経路として育てる。段階1でコードの差を埋め、段階2で有料確認が必要なものはそこで確かめる。
- **実験枠（labs）のまま**：v2の既定セットに載せない。必要な人だけが明示して使う。メンテナと実機証拠が揃うまで格上げしない。
- **v1 に残す**：いまのv1案件で完走する。v2へは完成動画のコピーや保管だけを使い、編集グラフは移さない。

表の「推奨案」列は提案です。所有者が別の列を選んでよいです。選んだ結果が段階1の作業範囲になります。

## 所有者に決めてほしいこと

1. 上の表で、推奨案と違う選択があるか。
2. 段階2で、PixVerse / ElevenLabs / Kling のどれを、どのアカウント上限で試すか。Klingは件数が少ないため、推奨案では実験枠のままです。
3. 段階3の3人と、公開するissueの中身（日本語クイックスタート案はalpha.5でほぼ済んでいます）。
4. 段階4以降の時期は、段階2と3の結果を見てから決める。M06の残りのフェーズゲートを続けるか見送るかも、このときに決める。

- 有料APIの実行、秘密情報の記入、`projects/` の変更。
- 案件名や個人の制作内容。
