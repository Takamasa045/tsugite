# v1からv2への移行判断

この文書は、継手の所有者が「次に何をするか」を決めた記録です。作業者がリポジトリと公開リリースから確認できた事実と、所有者が別途渡した手元の案件数をもとに書いた推奨案を、**所有者は 2026-10-19 にそのまま採用**しました。

## 所有者決定（2026-10-19）

- 下の表の推奨案を、変更せず採用する（Remotion / PixVerse / ElevenLabs は v2で対応。案件専用Remotion構成は v1 に残す。HyperFrames / MiniMax / Editframe / Hypit / Kling / Tesseract は実験枠のまま）。
- **段階2（有料受け入れ、P08 / P10 / B04）はいちばん最後に回す。** いまは課金しない。後で行うときは、いちばんクレジットが少ないサービスから試す。Kling は前払いクレジットが必要な場合がある。
- 段階1・段階3の準備（試用キットと issue 草稿）は、金を使わず進めてよい。確認ページ・予算・秘密情報の扱いを緩くしない。
- 版番号の繰り上げ、npm 公開、`projects/` の変更、有料 API、GitHub issue の作成は、この決定に含まれない。

いまの位置（2026-10-22）：

- いまの制作の正本は **v1 0.18.0**（`project.yaml` の案件）。v1 は保守として残る。新しい制作の案内は v2 を入口にする。版番号は上げていない。
- 試用用の独立配布は **v2 2.0.0-alpha.5**（`tsugite.yaml`）。正式版 2.0.0 の判定は、この文書の末尾を正とする。
- ElevenLabs の SFX は、実課金 1 件（2秒）を受け入れ済みとする。音声と music は未了。
- PixVerse・Kling・TopView は、API キーを設定に書く方式ではつながない。各サービスの CLI で、サブスクリプションにログインした状態で使う。対応は順次で、その実機確認は未了。
- 第三者3人の初回試用は未了。合成テストだけでは有料受け入れも実機確認も完了にしない。

案件名は書いていません。件数は所有者提供の集計です。

## 5つの段階

段階の番号は要件のまとまりです。実施順は **1 → 3 → 4 → 5 → 2** です。段階2（有料受け入れ）は番号では2番ですが、段階5のあとに回します。段階3の試用と issue 公開は段階2の完了を待ちません。

前の**実施順**の段階が終わる前に、次の段階の「公開」や「課金」を始めません。段階2の課金だけは、段階5のあと、所有者がアカウント・上限・対象サービスを指定してから行います。

| --- | --- | --- | --- |

いまのalphaを「正式なv2」や「制作の既定」にはしません。段階4の承認があるまで、既存の `project.yaml` 案件はv1で続けます。段階2の表のうち、PixVerse の完了条件は下の 2026-10-22 の補足が優先します。API キーでの有料受け入れは、正式版の条件から外しています。

段階3の3人試用は、M06が求める「各フェーズの独立ユーザーゲート」の**いまのalpha分**です。4フェーズ・14週間の全体を段階3で完了扱いしません。段階4へ進む前に、所有者が残りのフェーズゲートをどう扱うかを決めます。

## 採用した方針の読み方

3つの選択肢の意味は次のとおりです。所有者は推奨案どおりにこれを採用しています。

- **v2 で対応**：v2の本番経路として育てる。段階1でコードの差を埋め、有料確認が必要なものは段階2（最後）で確かめる。
- **実験枠（labs）のまま**：v2の既定セットに載せない。必要な人だけが明示して使う。メンテナと実機証拠が揃うまで格上げしない。
- **v1 に残す**：いまのv1案件で完走する。v2へは完成動画のコピーや保管だけを使い、編集グラフは移さない。

段階1の作業範囲は、表で「v2で対応」とした Remotion / PixVerse / ElevenLabs のうち、課金なしで閉じられる差です。

残っている所有者判断（段階3の3人の指名、公開する5件の issue、段階4以降と M06 の残り）は、段階1のコード作業と試用キット準備のあとに決めます。日本語クイックスタート案は alpha.5 で済んでいます。段階3の手順は [試用キット](onboarding/trial-kit.ja.md) と [contribution-backlog](contribution-backlog.md) にあります。

## 物語構成の引き継ぎ（2026-10-22）

調査対象の `f08f2c5` 以降、main に新しいコミットはありません。v2 には構成カタログも story plan もなく、短い story 知識パックと、素材の実物を見る guide だけでした。構成の正本はリポジトリの `knowledge/story-frameworks/catalog.yaml` です。v1 の選定コードは移していません。v1 の変更は、原則の件数を 35 から 36 へ直した `docs/story-guides.md` と、同じ件数を書いていた `docs/reference.md` / `docs/reference.ja.md` だけです。配布する v2 は正本と同じバイトを `v2/knowledge/story-frameworks/catalog.yaml` に同梱し、ライセンスと出典を同じディレクトリの `NOTICE.md` に置きます。相談はこの写しだけを読み、親リポジトリは探しません。同一性はテストで照合します。

`plugin story consult` は、画像・APIキー・FFmpeg・確認ページなしで構成相談を終えられます。依頼例は [物語・構成の相談](story-consult.ja.md) と [はじめての動画](onboarding/first-video.ja.md) にあります。採用した JSON を `story` として結ぶと、計画と確認ページに狙いとショット対応が出ます。構成を変えると既存の計画ハッシュが変わり、古い承認では先へ進めません。再確認対象は出しますが、素材は自動で作り直しません。

機械検証は id、尺、参照、仕込みのつながりです。意味が伝わるかは採点しません。`intentionally_unrecovered` と `missed` は別です。曲を未確認のとき、拍や歌詞時刻は作りません。`ranking_weight` は並び順であり、出来の確率ではありません。story plan のない古い案件は、これまでどおり計画できます。

この作業は課金・実生成・render・承認状態の拡張ではありません。段階2（P08 / P10 / B04）は引き続き最後です。出典が空のカタログ項目（構成 26/34、原則 19/36）は、空のまま区別して数えます。出典を後から作ることはしていません。2026-10-22 の `npm --prefix v2 run check` は **142 passed / 0 failed / skip 5** です。採用済み構成は除外後の全候補から id か名称で先に解決し、生成動画のタスク id は計画時と同じくショット参照に含めます。音声生成の id はショットにしません。
