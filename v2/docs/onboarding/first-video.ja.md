# はじめての継手：6秒の動画で環境を確認する

継手 / Tsugiteは、AIエージェントに動画の準備を手伝ってもらい、人が計画とできあがりを確認する道具です。このガイドでは、**練習用の映像をパソコン内で作り、6秒の縦長MP4を書き出します。** 動画生成サービスのアカウント・APIキー・クレジットは不要です。

[最初に試す用途と公開デモ](see-and-choose.ja.md)を見たい方は、先にそちらへ進めます。この6秒は作品の出来栄えではなく、導入と確認手順が動くことを確かめるサンプルです。

最初は追加の動画ツールを入れず、このサンプルで操作を確かめます。実際の生成サービスの品質や接続を試すものではありません。エージェント自体の利用料金は別です。

[READMEに戻る](../../README.ja.md#はじめての方はこちら) · [困ったとき](#困ったとき) · [英語の導入手順](../install.md)

## どこから始める？

- **まだ継手がない：** 下の「準備するもの」から読み、[公開済みalpha.5を導入](#公開済みalpha5を導入する場合)します。
- **すでにリポジトリを開いている：** [ローカル版の手順](#すでにリポジトリが手元にある場合)へ進みます。
- **コマンド操作を任せたい：** [エージェントへの依頼文](#エージェントに準備を頼む場合)を使えます。確認ページでの承認は自分で行います。
- **既存の`project.yaml`案件を使いたい：** [v1の案内](https://github.com/Takamasa045/tsugite/blob/v2.0.0-alpha.5/README.ja.md#v1の機能と詳しい使い方)へ戻ってください。この手順で既存案件を置き換えないでください。

v2は開発途中のアルファ版です。実課金サービスの受け入れ確認や、第三者が初めて使う試験はまだ完了していません。ここにある手順の確認と、第三者による使いやすさの検証は別です。

## 準備するもの

- **Node.jsとnpm：** コマンドで継手を動かすためのソフト。Node.js 22.12以上の22.x、npm 10以上を使います。単体のv2配布物はNode.js 22.12以上に対応しますが、リポジトリ本体は22.xを指定しています。
- **FFmpegとFFprobe：** 動画の作成と検査に使うソフト。FFmpegには`libx264`というMP4用の映像圧縮機能が必要です。
- **ターミナル：** コマンドを入力する画面。macOSなら「ターミナル」、WindowsならPowerShellなどを使います。
- **インターネット：** 配布ファイルと依存ソフトの取得に使います。準備が済んだ後のサンプル制作はオフラインです。

リポジトリをGitで取得する場合だけGitも必要です。公開alpha.5のファイルから試す経路ではGitは不要です。Remotion、HyperFrames、PixVerseなどは最初のサンプルに必要ありません。

ターミナルで次を1行ずつ実行して、ソフトの版が表示されるか確認します。

```sh
node --version
npm --version
ffmpeg -version
ffprobe -version
ffmpeg -hide_banner -encoders
```

最後の一覧に`libx264`があることを確認してください。不足があれば、使っているOSに合う導入方法を確認してから進みます。このガイドはシステムソフトを自動で追加しません。

## エージェントに準備を頼む場合

Codex・Claude Codeなど、**ローカルのフォルダを読み書きし、コマンドを実行できるエージェント**で使います。ブラウザのチャットに貼るだけでは、手元のパソコンへの導入は実行されません。

これから作業するフォルダを開き、次を貼り付けます。すでにリポジトリがある場合は、その場所も伝えてください。

```text
継手 / Tsugite v2で、外部サービスを使わない6秒のサンプルを試したいです。
このガイドを読んで、使える版と環境を確認し、準備を手伝ってください。
公開済み版の案内：
https://github.com/Takamasa045/tsugite/releases/tag/v2.0.0-alpha.5

すでにリポジトリがある場合は、このフォルダのAGENTS.mdと
v2/skills/tsugite/SKILL.md、docs/onboarding/first-video.ja.mdを読んでください。
ローカル更新と公開済みalpha.5を区別し、既存のフォルダは上書きしないでください。
まだない場合は、公開済みalpha.5の配布ファイルとSHA256SUMSを取得し、
チェックサム確認後に新しいフォルダへローカル導入してください。

最初にNode.js・npm・FFmpeg・FFprobeを確認してください。

無課金サンプルのinit、check、planまで進め、確認ページのURLを教えてください。

```

alpha.5の配布ファイルには、日本語READMEとこの導入ガイドも含まれます。エージェントには、導入先のREADME.ja.mdとskills/tsugite/SKILL.mdを読んでもらえます。すでにローカルで使える版がある場合、公開版の導入に置き換える必要はありません。

## 公開済みalpha.5を導入する場合

### 1. ファイルを取得して確かめる

[GitHubのalpha.5配布ページ](https://github.com/Takamasa045/tsugite/releases/tag/v2.0.0-alpha.5)の「Assets」から、次の2つを新しい空の作業フォルダに保存します。

- `tsugite-2.0.0-alpha.5.tgz`：継手のプログラム。
- `SHA256SUMS`：ダウンロードしたファイルが一致するか確かめるための値。

この配布はプログラムと照合用ファイルのみです。完成サンプルの動画・画像やDesktopインストーラーは含みません。**npmレジストリには公開していないため、`npx tsugite`や`npm install tsugite`でこの版を取得しないでください。**

ターミナルをその作業フォルダで開き、次で照合します。

macOS：

```sh
shasum -a 256 -c SHA256SUMS
```

Linux：

```sh
sha256sum -c SHA256SUMS
```

WindowsのPowerShell：

```powershell
Get-FileHash .\tsugite-2.0.0-alpha.5.tgz -Algorithm SHA256
Get-Content .\SHA256SUMS
```

macOS・Linuxではファイル名の後に`OK`が出ること、Windowsでは2つのハッシュ値（英数字）が同じことを確認します。英字の大文字・小文字の違いは問題ありません。一致しなければ導入せず、取得したファイルを確認してください。

### 2. ローカルに導入し、練習用の動画フォルダを作る

同じ作業フォルダで、1行ずつ実行します。`tsugite-local`と`my-video`は新しく作るフォルダです。すでに同名がある場合は別の空の作業フォルダを使ってください。

```sh
npm install --prefix ./tsugite-local --ignore-scripts ./tsugite-2.0.0-alpha.5.tgz
node ./tsugite-local/node_modules/tsugite/bin/tsugite.mjs init ./my-video
node ./tsugite-local/node_modules/tsugite/bin/tsugite.mjs check --project ./my-video
node ./tsugite-local/node_modules/tsugite/bin/tsugite.mjs plan --project ./my-video
```

最初の行は依存ソフトを取得するためネットワークを使います。パソコン全体のコマンドを置き換えるグローバル導入ではありません。`check`の結果が`"ok": true`になることを確認します。

最後の`plan`は確認ページのURLを表示します。ブラウザは自動では開きません。表示された`http://127.0.0.1:...`を自分で開いてください。自動で開く場合だけ`--open`を付けます。**このターミナルは動かしたまま**にして、[確認ページでの操作](#確認ページでの操作)に進んでください。

### 3. 計画を承認したあとに書き出す

確認ページで**Approve plan**を押した後、**2つ目のターミナルを同じ作業フォルダで開き**、次を実行します。

```sh
node ./tsugite-local/node_modules/tsugite/bin/tsugite.mjs make --project ./my-video
node ./tsugite-local/node_modules/tsugite/bin/tsugite.mjs export --project ./my-video
```

動画は**`my-video/out/final.mp4`**です。[完成を確認する](#完成を確認する)へ進みます。

## すでにリポジトリが手元にある場合

これは**手元のソース版**を使う経路です。公開済みalpha.5の配布ファイルとは別です。GitHubのmainには配布後の変更が加わることがあり、手元だけの追加更新がある場合はmainとも内容が異なります。版番号が同じでも、追加ツールが同じ版に更新されているとは限りません。[対応範囲と追加プラグインの条件](../plugins.md)を確認してください。

### 1. リポジトリ直下で準備する

`package.json`と`v2/`が見えるフォルダで実行します。Node.jsとFFmpegの準備は前述のとおりです。v2の依存ソフトがまだない場合だけ、次を実行します。ネットワークを使い、`v2/node_modules`を整えます。

```sh
npm --prefix v2 ci --ignore-scripts
```

v2のサンプルだけを試すために、v1の`npm run setup`や追加エンジン一式を導入する必要はありません。

### 2. 新しいサンプルの計画を開く

```sh
npm run --silent v2 -- init ./my-first-v2-video
npm run --silent v2 -- check --project ./my-first-v2-video
npm run --silent v2 -- plan --project ./my-first-v2-video
```

v2 の設定と好みは `~/.tsugite`（上書きは `TSUGITE_HOME`）です。v1 の
`TSUGITE_PROJECTS_HOME` は読みません。リポジトリの `projects/` に書かないでください。

`check`が`"ok": true`になったことを確認してください。`my-first-v2-video`がすでにある場合は、3行とも同じ新しい名前へ変えます。既存の制作案件を指定しないでください。

`plan`のターミナルは動かしたままにして、表示された確認ページのURLを自分で開き、[確認ページでの操作](#確認ページでの操作)に進みます。

### 3. 計画を承認したあとに書き出す

確認ページで**Approve plan**を押した後、**2つ目のターミナルをリポジトリ直下で開き**、次を実行します。

```sh
npm run --silent v2 -- make --project ./my-first-v2-video
npm run --silent v2 -- export --project ./my-first-v2-video
```

動画は**`my-first-v2-video/out/final.mp4`**です。

## 確認ページでの操作

`plan`が表示した確認ページで、作品名・縦横比・長さ・素材・サービスごとのクレジットを確認します。画面は現在英語です。

| 画面の表示 | 意味と操作 |
| --- | --- |
| **Plan & storyboard** | 素材と順序、計画を確認する欄。今回の長さは6秒、縦横比は9:16です。 |
| **Credits by service** | サービス別の予算と見積もり。今回のローカルサンプルは生成サービスを使いません。 |
| **Approve plan** | 内容がよければ自分で押して、計画を承認します。 |
| **Approve clips** | 素材の確認・承認。今回のサンプルは新しい素材の生成がなく、自動通過を明示設定しています。ほかの案件では人による素材確認が必要です。 |
| **Final preview / Approve final** | 書き出し後の動画を再生し、最後に完成内容を承認します。 |

承認はこの確認ページだけで行います。CLI（コマンド入力）やMCP（エージェントとの接続）からの承認はできません。エージェントにボタン操作や承認データの書き換えを頼まないでください。同じOS権限で動くエージェントから完全に隔離する仕組みではありません。

設定や素材を変えたら、もう一度`plan`で計画を作って確認します。古い承認のままで変更後の動画を実行することはできません。

## 完成を確認する

1. `export`が成功したら確認ページを再読み込みします。
2. **Final preview**または保存された`out/final.mp4`を開き、映像と長さを確認します。音声付きの自分の動画では音も確認します。
3. よければページで**Approve final（完成動画を承認）**を押します。
4. 終えるときは`plan`を動かしていたターミナルで`Ctrl+C`を押します。動画や素材はフォルダに残ります。

これで「計画を確認 → 素材を準備 → MP4を書き出す → 完成を確認」の一巡です。今回の標準サンプルは単純な練習映像で、商品紹介やAI生成映像ではありません。

## サンプルの次に頼めること

素材の場所・長さ・縦横比・字幕や音の希望を伝えます。最初は、コピーした素材を使う新しい案件で試してください。

| やりたいこと | エージェントへの依頼例 |
| --- | --- |
| 手元の動画を短くする | 「この動画の10秒〜25秒を使い、縦長の15秒動画にしたいです。元ファイルを残して、新しいv2案件の計画まで準備してください。」 |
| 字幕を入れる | 「この動画とSRT字幕を使いたいです。字幕の時間と動画の長さが合うか確認し、まず計画を見せてください。」 |
| 好みを残す | 「『冒頭を短くしたい』を今回の好みメモに残してください。次の修正案を出し、実行前に確認ページで止めてください。」 |
| 新しいAI映像を生成する | 「使えるサービスと未検証の点、必要な接続設定、サービスごとのクレジットを先に説明してください。まだログイン・課金・生成しないでください。」 |

希望はエージェントが対応範囲を確認して設定へ反映します。好みメモを残しただけで動画を自動修正する機能ではありません。外部サービスを使う場合は、素材の送信先・接続・利用条件・予算を別途確認します。異なるサービスのクレジットは合算しません。

## 困ったとき

| 状態 | 確認すること |
| --- | --- |
| `node`・`npm`・`ffmpeg`・`ffprobe`が見つからない | 対象ソフトの導入と、ターミナルから呼べる設定（PATH）を確認します。導入後はターミナルを開き直します。 |
| `Unknown encoder 'libx264'`などが出る | FFmpegの`-encoders`一覧に`libx264`があるか確認します。`check`の成功だけでは、この圧縮機能まですべて確認できません。 |
| `package.json`がない／`Missing script: v2` | リポジトリ版なら、`v2/`とルートの`package.json`があるフォルダで実行します。配布版なら`node ./tsugite-local/...`の手順を使います。 |
| `Cannot find package 'yaml'` | リポジトリ版は`npm --prefix v2 ci --ignore-scripts`が成功したか確認します。配布版はローカル導入が成功したか確認します。 |
| `EEXIST`／同名フォルダがある | `init`は新しいフォルダに作ります。別名を選び、以降の`--project`も同じ名前にします。既存フォルダを削除しないでください。 |
| 確認ページが開かない | 既定ではブラウザは開きません。`plan`が表示した`url`の`http://127.0.0.1:...`を同じパソコンのブラウザで開きます。自動で開く場合は`--open`を付けます。ターミナルは動かしたままにします。停止した場合は同じ案件で`plan`を再実行します。 |
| 承認待ちで`make`や`export`が止まる | 同じ案件の確認ページを再読み込みし、待っている確認段階を読みます。計画・素材・完成のどれかを、内容確認後に自分で承認します。 |
| 素材や設定の変更後に止まる | `plan`で変更後の計画を作り直し、再度ページで確認します。承認ファイルを手で修正しないでください。 |
| 初回導入でネットワークエラー | 取得段階にはインターネットが必要です。接続・エラー内容を確認し、成功してから制作に進みます。 |

解決しない場合は、**使っているOS・公開配布版かローカル版か・実行したコマンド・エラー文**を添えて相談してください。APIキーや認証ファイルは貼らないでください。外部サービスで結果が不明な失敗が起きた場合は、クレジットの二重消費を避けるため自動再試行せず、結果を確認します。
