# 物語・構成の相談

構成の相談は、画像・APIキー・FFmpeg・確認ページの承認がなくても始められます。ここでの結果は助言です。生成、外部送信、課金、Gate 承認は行いません。採用した構成メモを案件へ結んだあとで、いつもの `plan` が確認ページを開きます。

カタログはリポジトリの `knowledge/story-frameworks/catalog.yaml` をデータとして読みます。v1 の選定コードは使いません。`ranking_weight` は候補の並び順であり、出来の確率ではありません。出典が空の項目は、カタログに出典がないという記録のままにします。

## 入口

最初に聞くのは、何を残したいか、長さ、残したいもの、の三つまでです。

| 入口 | `--entry` | 相談で要らないもの | 制作へ進むときに要るもの |
| --- | --- | --- | --- |
| アイデアから | `idea` | 画像、APIキー、FFmpeg、承認 | 採用した構成、映像か生成タスク、確認ページ |
| 台本を直す | `script` | 同上 | 直した台本、ショット対応、確認ページ |
| 曲・歌詞・素材から | `material` | 同上。未確認の拍や歌詞時刻は作らない | 確認できた曲・歌詞・素材、確認ページ |
| 決めた構成を映像へ | `decided` | 同上 | 採用した構成メモ、映像か生成タスク、確認ページ |

```sh
npm run --silent v2 -- plugin story consult --request "60秒の静かな自然映像。ドラマ・CTA不要" --seconds 60
```

`--output story/draft.json` を付けたときだけ、構成メモの下書きをそのファイルへ書きます。案件の設定や承認は変えません。

下書きのビートは、選んだ型の段階名だけを `source: framework-flow` として持ち、見える行動は未定のままです。未定・不明・適用外の欄に本文は入れません。

演出の既定は、用途と例外つきの助言です。静かな観察では、冒頭1秒のフック、寄りと引きの交互、山場の彩度上昇は例外です。曲の拍に合わせる助言は、拍が確認できるまで使いません。

## 依頼例

| やりたいこと | エージェントへの依頼例 |
| --- | --- |
| 短編 | 「90秒の短編を、アイデアから構成だけ相談したい。主人公は一度だけ選び、画像も生成もまだ不要。」 |
| 台本診断 | 「20秒の台本を直したい。夜のホーム。Aは『もう行く』、Bは『待って』。Aは振り返らず去る。残したいのは二人の距離。診断まで。」 |
| MV | 「90秒のMVにしたい。曲はまだ聴いていない。歌詞の時刻は不明。拍や歌詞時刻を作らず、構成だけ相談したい。」 |
| 民話 | 「3分の民話。昔話の起こりと余韻を残し、広告の締めにはしない。脚色してよい範囲と、残す原話の要素を先に分けたい。」 |
| 静かな映像 | 「60秒の静かな自然映像。ドラマ・CTA不要。人物の成長や申込みの締めは使わない。」 |
| 採用案を制作へ | 「採用した構成メモをこのv2案件へ結び、計画の確認ページまで出して。生成も承認もまだしない。」 |

制作へ進むときは `plugin story check story/plan.json` のあと `plugin story bind story/plan.json` を使い、続けて通常の `plan` を実行します。`check` は id、尺、参照の機械検証だけです。理由が伝わるかの意味レビューは自動化しません。

## 構成メモ

正本は案件内の JSON です。`tsugite.yaml` の任意項目 `story` がそのパスを指します。項目がない古い案件は、これまでどおり計画できます。

記録するのは、形式と範囲、観客体験、採用理由、残す要素、意味ビート（`before` / `visible_action` / `after` / `caused_by` / `shot_refs`）、未決、カタログ revision です。人物の選択、情報開示、仕込みは、必要な形式だけの任意モジュールです。`intentionally_unrecovered` は作者が理由を書いた未回収で、`missed` の回収漏れとは別です。

`shot_refs` はタイムラインのクリップ id（`input-0` や生成タスク id）です。場所の scene や、音楽の拍番号ではありません。歌詞は、作者が `music.cues` に書いた cue id だけを参照します。

構成メモを変えると、既存の計画ハッシュが変わり、古い承認では `make` に進めません。変わったビート、および結末に関係する仕込みとショットが再確認対象になります。素材の自動再生成はしません。

## 完成見本（初稿→診断→改稿→ショット）

### 初稿

20秒。夜のホーム。A「もう行く」。B「待って」。Aは振り返らず歩き出す。残したいのは二人の距離。

### 診断

相談では、この台本の見える行動を創作で埋めません。機械的には、選択の前後がまだ未定です。意味の確認（自動では採点しない）では、Aが去る理由が画になっておらず、時計を見る仕込みがありません。冒頭1秒のフックと、山場で彩度を上げる処理は、この対話の既定にしません。

### 改稿

Aは時計を見て、まだ乗れると知る。Bの「待って」で立ち止まる。終電を見送り、二人で残る。ポケットの手紙は開かず、意図して謎のまま残す。電車の実音を使うかは未決のままにする。

正本の見本は [story-plan-platform.json](../packs/examples/story-plan-platform.json) です。

### ショット対応

| ビート | 見える行動 | ショット | 仕込み |
| --- | --- | --- | --- |
| `b-clock` | Aが時計を見る | `input-0` | 時計は `b-stay` で回収。手紙は意図的に未回収 |
| `b-call` | Bの「待って」で立ち止まる | `input-0` | `b-clock` が原因 |
| `b-stay` | 並んで電車を見送る | `input-0` | 時計の回収 |

結末を「去る」に変えると、`b-clock` と `b-stay` のショットが再確認対象になります。クリップ自体は自動では作り直しません。
